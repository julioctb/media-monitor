### Bounded directory versus publication history

- Directory loading remains **up to 200** server-ranked identities per search. Ascending mention sort, followed-person filtering, header counts and 25-row client pages describe that loaded pool, **not global ascending/followed results**. The current page-header, Fuentes badges, default descending order and cookie seed are retained. No server-directory pagination envelope is introduced.
- `listPersons()` retains array and optional `{items}` normalization, including the existing missing-items-to-empty compatibility. `PersonOut.sources` and its tenant-filtered distinct-source query remain unchanged.
- Modal publication requests use a separate same-origin `/api/persons/[id]` gateway, `limit=25`, independent `offset` and `order=recent`. The backend supplies `timeline_total`, `timeline_limit`, `timeline_offset` and `timeline_order`; default detail behavior and tenant guards remain. Timeline order uses publication time, ingestion fallback and ID tie-breaking.
- A bounded timeline page never becomes a historical tone distribution or a global related-event count. Events are explicitly labelled as belonging to the current page. Older responses without optional timeline metadata retain the conservative previous/next fallback without inventing a total.
- Shared dialog Escape, opt-in backdrop dismissal and focus return are composed with the **current parent-driven close behavior**, not copied over it. Closed/replaced requests cannot overwrite a newer identity; paging does not reset the directory or the modal offset.
- Source links reuse `safeEvidenceUrl`; unsafe/non-HTTP(S) URLs remain inert and quotations render as text. The gateway returns generic Spanish 404/unavailable messages instead of reflecting upstream diagnostics.
